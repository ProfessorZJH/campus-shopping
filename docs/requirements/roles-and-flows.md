# 用户角色、权限矩阵与端到端业务用例

> 版本 v1.0 · 2026-10-26 · **产品用例定义，不代表界面/API 已实现**。以 [PRD](PRD.md) 的角色范围为准。

## 1. 用户不是互斥的角色枚举

一个 `UserAccount` 可同时以消费者身份下单，在商户 A 拥有 OWNER，在商户 B 拥有 CLERK；平台管理员身份从受控初始化获得，不通过普通注册。商户的营业资格属于 Merchant 上下文，与 Identity 的成员权限是两套不同判断。

## 2. 权限矩阵

| 操作 | 匿名 | 消费者 | OWNER（本人所属商户） | CLERK（本人所属商户） | PLATFORM_ADMIN |
|---|---|---|---|---|---|
| 浏览公开上架商品 | ✓ | ✓ | ✓ | ✓ | ✓ |
| AI 购物对话 / 加购 | 登录后 | ✓ | ✓ | ✓ | ✓（以买家身份） |
| 查询本人订单/售后 | × | ✓ | ✓（仅本人） | ✓（仅本人） | 按受控运营权限 |
| 申请商户入驻 | × | ✓ | ✓ | ✓ | ✓（仍不能审本人） |
| 审核/停用商户 | × | × | × | × | ✓ |
| 编辑商户商品/价格 | × | × | ✓ | ×（首版） | 仅违规下架管理权限 |
| 商户补货 | × | × | ✓ | ✓（需本商户补货权限） | ×（非直接经营者） |
| 备货/核销 | × | × | ✓ | ✓ | ×（不默认代店员核销） |
| 管理商户员工 | × | × | ✓ | × | 必须显式授权审计（非默认） |
| 审批本商户售后 | × | × | ✓ | ×（首版） | 仅平台纠纷裁决 |
| 维护商户知识库 | × | × | ✓ | ×（首版） | 仅平台自有知识及监管 |

平台管理员不是所有商户数据的超级 Owner；监管权限应精确到审核、停用、查看/纠纷等操作，不能用一个 `admin=true` 直接跳过所有业务规则。

## 3. 业务流程与验收条件

### UC-01 注册登录

访客提交用户名/密码 → 服务端校验唯一与密码策略 → 保存安全密码哈希 → 登录建立安全会话 → 查询当前账号 → 退出销毁会话。错误：用户名冲突、密码错误、已禁用账号、过期会话。验收：未登录不能查询本人购物车；平台角色不会因普通注册产生。

### UC-02 商户入驻与开通

用户提交商户名称/经营类别/联系信息/首店位置 → PENDING 审核 → 平台管理员通过/驳回。通过后原子创建 Merchant/Store/OWNER Membership 并审计；驳回必须有原因。验收：本人不可审核；重复通过不重复建商户；原子事务失败全回滚。

### UC-03 商户经营准备

OWNER 创建商品草稿 → 添加多个 SKU/售价 → 上架 → 店员按 SKU 补货 → 商品公开可浏览。错误：规格重复、商户停业、售价非法、跨商户访问。验收：商户 A 不可修改商户 B 商品或库存。

### UC-04 消费者交易

用户跨商户浏览和加购 → 购物车按商户分组 → 选择一家商户结算 → 服务端真实报价、全 SKU 库存原子预占 → 创建 PENDING_PAYMENT 订单 → 模拟支付 → 订单进入待备货。错误：价格变化、库存不足、订单超时、重复提交。验收：库存不超卖，无法出现未预占却可支付订单。

### UC-05 自提履约

付款成功 → 幂等创建 PickupTask → 商户接单备货 → 生成自提凭证 → 消费者到店展示 → 有权店员核销 → 同事务完成订单、消耗库存预占并扣实际库存。错误：无效码、过期、二次核销、他店店员、已退款订单。验收：最多一次核销与一次出库。

### UC-06 未提货退款

买家对已付款未核销订单申请全额模拟退款 → 本商户 Owner 审核 → 成功后取消待提货任务、释放原库存预占、写模拟退款事实 → 标记 REFUNDED。错误：已核销、重复申请、非本人申请、跨商户处理。验收：退款与核销不可能双成功。

### UC-07 智能导购

输入预算/用途/偏好 → Python 理解并检索授权知识和真实商品候选 → Java 复核实时商品/价格/库存 → 生成带解释与商品卡的 Proposal → 用户明确确认 → Java 再次校验并加购。错误：提案过期、商品下架、他人提案、LLM 不可用。验收：模型不执行无确认写操作。

### UC-08 知识维护

商户 Owner 创建知识库/上传文档 → 权限和文档版本校验 → 异步索引 → 索引成功才能发布版本 → 公开知识允许消费者引用，内部知识只能授权员工访问。错误：索引失败、权限不足、旧版本已撤回。验收：跨商户/公开渠道不可泄露内部文档。

## 4. 业务对象与 UI 关系

三个使用端拥有独立导航，但共享同一可信 Java 业务 API：消费者端关注“商品→购物车→订单→自提”；商户端关注“店铺→商品→库存→备货→售后”；平台端关注“申请审核→商户治理→运营统计/纠纷”。UI 控件隐藏不是授权，最终授权在后端执行。
