## 2. 推荐准备的正式图件

- 校园平台用户用例图、主要业务活动图。
- 七上下文领域边界图和上下文映射图。
- 商品/库存/订单/自提/AI 提案状态机。
- Java 六边形架构与依赖倒置示意图。
- 主要实体 ER 图与业务数据库索引设计。
- 下单与预占、核销与库存、AI 推荐与确认的时序图。
- 三端关键页面截图及核心功能演示视频。
- AI/RAG 召回消融实验的真实结果图表。

这些图件可以从 Markdown Mermaid 初稿生成论文插图，但必须保证与最终代码和实际数据表一致；不能把未实现的设计图当作“已完成系统图”。

## 3. AI/RAG 创新点的证据要求

可以研究：复合意图提取、混合检索与重排、知识引用权限、推荐建议受控执行。但论文中要同时展示基线 E0 和改进 E1–E4 在**同一固定测试集**上的真实指标；每张表需标注版本、样本数、计算方法，不能编造 Recall@5 及压测数据。

## 4. 业务工程亮点的证据要求

- MySQL 并发库存防超卖（最后一件压力测试、事务隔离/条件更新）。
- 商户审批与 Owner 授权原子性（故障回滚）。
- 模拟支付与超时取消状态竞争（一次合法终态）。
- 自提核销与未提货退款竞争（不双成功）。
- AI 仅提出建议、用户确认后可信执行（越权与过期测试）。

这些“可测试证据”比堆很多设计模式名称更能证明毕业设计工程能力。

## 5. 毕业设计过程记录规范

每个阶段保存：业务需求变更、领域建模版本、代码提交 SHA、数据库迁移版本、测试结果、问题修复记录、页面截图、实验配置与原始数据。演示采用模拟支付，必须明确标注，不得写成真实资金生产交易。导师评价、验收结论只能引用实际确认材料。
