# R1 容量、恢复与外发操作

本版支持多个Java实例共享MySQL/Redis和一个Python实例。Python SQLite及本地图片目录仍需持久卷；不支持把它们复制为多个独立Python实例。以下配置不授权替换现有服务或迁移业务库。

## 扫描和恢复

订单扫描每15秒最多20批、每批100笔，按订单ID稳定翻页。失败单记安全诊断与累计失败数，继续后续订单；到末尾后下轮重新检查失败单。重启从头重扫，由逐订单事务幂等复验保护。`order_expiry_scan`包含最久逾期秒数，持续增加时应告警；扫描失败也累计计数。

商品同步每轮最多100批、每批40件，全目录按ID翻页，实时公开状态决定index/delete。每批远程操作全部成功后，MySQL `ai_sync_checkpoint`才推进。远程成功但保存失败可幂等重放；重启或换Java实例使用同一checkpoint继续。扫尾后清空游标，下一周期发现游标以前的更新和新商品。Redis锁竞争记录skip_total，锁故障记录安全诊断并累计失败；不可把长期无成功记录当健康。

备份并停止旧实例后显式应用`V20261031_03`，应用启动只读校验。回退代码时保留checkpoint表和迁移历史，不删除数据。新建临时库与迁移重放验证见整改记录。

## 探针及容量

`GET /health`为存活探针；`GET /ready`须`X-Service-Key`。SQLite不可读返回503；外部能力故障返回200 DEGRADED以保留本地导购及普通商城。报告实际调用的最近成功/失败时间，未调用为UNVERIFIED，无配置为DISABLED；不为探针额外调用供应商。

execution报告capacity、active、queued=0、rejected。系统不排队，满载返回429，实际执行完成后才释放。故障时间晚于成功时间、rejected持续增长、最久逾期增加、同步长时间无成功都应由部署侧采集告警。进程计数重启清零，checkpoint保存在MySQL；本次没有部署指标采集器。

HTTP响应先限制实际流字节再解析JSON，LLM上限256KiB、Embedding 8MiB、Qdrant 4MiB；拒绝压缩响应，禁止重定向，声明长度和实际读取均受限。超限按现有依赖失败/本地降级语义处理。

## 知识外发

PUBLIC知识可外发；内部知识默认仅本地字符向量/BM25。服务端`AI_EGRESS_BASE_IDS`为逗号分隔的批准知识库ID；MERCHANT_INTERNAL还须其商户出现在`AI_EGRESS_MERCHANT_IDS`。PLATFORM_INTERNAL须无商户且知识库获批，未知可见性拒绝。需先完成数据范围审核再配置，不能由客户端指定。两个变量分别映射`campus.ai.egress.base-ids/merchant-ids`。

Java逐次从授权可见范围构造外发document ID名单，Python默认拒绝。只有名单内证据进入模型上下文，历史只保留最近3条user消息，不外发assistant历史。文本截断并脱敏手机号、身份证号及邮箱；这是基础规则，不保证识别所有个人信息。Embedding输入同样处理。审计仅含供应商主机、用途、时间、记录数、字节数、请求ID；Java记录已批准索引请求，不记录正文。

撤回批准后，后续检索不再查询该文档的远端向量或将证据发给LLM，但不会撤回历史已发出的数据。重新索引可改为本地模式；既存供应商数据须依供应商保留政策另行授权清理。不得宣称此更改自动完成历史数据删除。
