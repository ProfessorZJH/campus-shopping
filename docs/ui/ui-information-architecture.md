# 三端信息架构与交互设计说明

> **R1 对齐说明（2026-10-28）**：本文保留需求来源与历史设计；当前冻结规则以 [R1 实施规格](../specs/RELEASE-01.md) 为准，实际实现/验证状态见 [R1 交付清单](../DELIVERY-R1.md)。历史“下一批/待开发/已通过”描述不作为本次执行证据。

> 版本 v1.0 · 2026-10-26 · **页面/交互设计稿，非前端源码或像素级视觉稿**。真实功能以 PRD + 领域契约为准。

## 1. 设计原则

- 三端共享同一业务语义和服务器权限规则，不共享所有菜单。
- 列表按用户目标组织，不做无意义的大型中文「工作台」和一屏堆砌所有指标。
- 用户操作状态、成功/失败、加载/空态与异常恢复应明确；不要显示内部 LangChain/Qdrant 调试细节。
- AI 回答提供简洁商品卡、明确出处和确认操作；“推荐建议”和“已加购”必须有不同视觉状态。

## 2. 消费者端（移动优先）

| 页面 | 核心内容 | 关键交互 | 后端来源 |
|---|---|---|---|
| 首页/搜索 | 商户入口、分类、搜索框、商品卡 | 搜索、切商户、打开商品 | Catalog 查询 |
| 商品详情 | SKU、真实售价、简介、库存提示 | 选规格、数量、加入购物车 | Catalog + Inventory |
| AI 导购 | 聊天流、商品推荐卡、授权公开引用 | 追问、建议确认/拒绝、失败重试 | ShoppingAI + Trading |
| 购物车 | 按商户分组、数量、实时价格提示 | 选定一个商户结算 | Trading + Catalog |
| 结算/模拟支付 | 商品快照、总金额、过期倒计时 | 提交订单、确认模拟支付 | CheckoutCase/Trading |
| 订单/自提 | 状态时间线、自提凭证、售后 | 查看进度、申请退款 | Trading + Fulfillment |
| 个人账号 | 我的商户身份、会话退出 | 登录/退出 | Identity |

## 3. 商户端（桌面/平板优先）

| 页面 | 核心内容 | 权限与约束 |
|---|---|---|
| 商户资料 | 经营名称、门店地点、营业状态 | 仅本商户，停用需明示 |
| 商品 SKU | 商品列表、编辑、发布、规格与售价 | Owner；报价变更有版本冲突提示 |
| 库存 | 每门店 SKU 的 onHand/reserved/available | 有权员工补货，显示库存流水 |
| 订单/待备货 | 状态筛选、明细、备货任务 | 仅本商户店员与 Owner |
| 自提核销 | 输入/扫码核销、状态反馈 | 明确无效/重复/已退款结果 |
| 售后 | 待处理、申请理由、批准/驳回 | Owner 审批，留审计 |
| 员工与知识库 | 邀请/撤权、知识上传和索引状态 | Owner；内部知识不公开 |

## 4. 平台管理端

待审入驻申请 → 申请资料审核与决定 → 商户治理 → 纠纷处理（P4）→ 必要经营统计（P6）。平台管理员执行拒绝、停用、纠纷裁决等高影响操作时要求确认并填写必要原因，操作记录可审计。**平台不默认进入商户后台直接变更库存。**

## 5. 通用交互状态

| 场景 | 必须展示的状态 | 失败恢复 |
|---|---|---|
| 商品加载 | 加载、空结果、下架、缺货 | 重新检索/换 SKU |
| 结算变价 | 原价/现价差异、用户确认 | 重新报价，不静默支付 |
| 库存不足 | 缺货 SKU、可调整数量 | 返回购物车 |
| 模拟支付到期 | 截止时间、已关单 | 新建订单重新结算 |
| 自提已核销 | 已完成，不再显示可用凭证 | 查看订单记录 |
| AI 提案过期 | 明确过期标签 | 重新生成建议 |
| SSE 断线 | 已收到的文本与未完成状态 | 重试/恢复，不自动执行写命令 |
| 无权限 | 友好但不泄密的提示 | 返回有权限的入口 |

## 6. 前后端边界

浏览器只能操作公开 API；所有商户权限在后端按当前 userId+merchantId+permission 验证。商品卡用于展示，不代表成交事实；下单重新报价。模型推荐按钮只有用户实际点击确认、Java 完成事务后才能显示“已加入购物车”。

## 7. 后续视觉稿与验收

正式 UI 开发前产出三个端的关键页面线框，确认移动屏幕导航、角色切换、响应式布局和无障碍交互；前端 E2E 验收按 [测试矩阵](../testing/e2e-acceptance.md) 执行。当前没有声明已生成正式设计稿。
