# 校园商城 Agent v1.1 · 方案收敛与冻结文档包

日期：2026-11-06。适用项目：`ProfessorZJH/campus-shopping`。

**交付性质：可用于评审和拆解开发的推荐设计，不是已经实现或已经验收的软件。** 本次从已有 PR #55 的设计出发，整理所有已讨论模块的可用方案，给出一个面向当前约束的推荐组合。整合初稿生成时尚未修改远端 PR；现将此文档组提交到现有 Draft PR #55，不涉及业务代码修改、合并或真实模型/业务测试。

## 结论

推荐：**统一 AI 交互 + 两组内部业务能力 + 每轮范围解析 + 带来源的实体/约束记忆 + 有界 Scoped Run + Java Tool Gateway/业务校验**。

运行时首选验证 OpenAI Agents SDK；沿用 Java Session/CSRF、现有 RBAC、Case/Domain、MySQL、现有 RAG 与 Milvus 商品检索。不新增用户 JWT，不建立常驻 Task/Workflow 系统，不将 Redis 的活动角色当成权限真相。

“每轮解析”不是每轮忘记历史，也不是每轮必须多调一次分类模型。系统保留实体、约束、来源和动作回执；只是每轮重新决定本次可使用哪些资料和能力。对于复杂跨天任务，未来再引入业务 Task，不为买家/商家身份切换提前建任务平台。

## 哪些内容冻结，哪些不得假装已经确定

**建议冻结的业务与安全规则：** 不要求选择工作空间；普通推荐不等于加购授权；明确低风险加购不重复确认；高风险动作必须绑定预览后确认；运行范围不能替代当前权限；原始事实有来源；真实价格/库存/订单状态由 Java 裁决；记录真实执行结果。

**待 POC 验证后锁定的实现项：** SDK 精确版本、当前第三方模型的 tool_calls/结构化输出/流式兼容性、模型上下文预算、并发及总超时、Trace 导出目标。

**实施前必须落地的契约：** 下面提供了目标接口和逻辑字段，但尚未在仓库生成 OpenAPI、DDL 迁移或代码。具体数据库列类型、索引、SDK 版本等应在实施 PR 中按本文行为契约细化并验证。不要把本文的接口建议写成“现有接口”。
