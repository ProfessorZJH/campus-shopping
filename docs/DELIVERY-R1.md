# R1 源码交付说明

## 结论

七个业务领域、跨领域用例、三端页面、Python 检索服务、部署与验收脚本均已写入工程。2026-10-29 已完成[本机真实 Spring/MySQL、AI 导购与浏览器交易闭环验收](testing/LOCAL-LIVE-20261029.md)：173 项 HTTP 检查及列明的页面、角色、数据库核对通过，原始失败与复测保留。Docker、Qdrant、生产部署和性能验收不在该结论范围；有限验收不等于没有任何集成缺陷。此前独立 AI 子链路见[前序报告](testing/AI-LIVE-20261029.md)。

工程化后续修复及隔离库验证见 [ENGINEERING-10](testing/ENGINEERING-10.md)。交付清单由每次 Maven verify 生成到 `campus-shopping-app/target/release-manifest.json`，记录实际 JAR、源码和测试摘要；根目录旧静态清单已移除。标准源码构建增加 Node22.16.0 / Python3.11 要求，已有库必须通过显式迁移入口登记版本后再启动。

## 本轮真正修正的规格问题

1. 旧申请只有商户名称：补齐经营类别、联系人、电话、门店与位置，缺资料的旧申请不得开通。
2. 单库支付与履约不必先异步：付款记录和自提任务同事务创建，防止已付款无履约任务。
3. 统一退款与核销锁序：锁订单，校验状态，再按稳定SKU顺序处理预占/实物。
4. 购物车并发写入必须串行：买家购物车专用锁行，避免确认提案与结算相互覆盖。
5. 请求键和SKU规格键大小写语义明确：保存与查询统一、数据库唯一键区分大小写。
6. 本地BCrypt属于凭据存储处理，继续在账号Repository中实现；Port仅连接Python远程服务。
7. 未配置模型时返回明确演示标识，不称为真实大模型、语义Embedding或生产RAG效果。
8. 旧脚手架示例Mapper引用不存在的PO，已删除；它与通配Mapper加载冲突，不能保留到当前运行包。

## 实现仍有明确边界

- Java/Spring/MySQL与实际BCrypt全链路未运行；Maven 构建和非 MySQL 测试已通过，完整运行正确性仍需真实数据库验收。
- 无模型密钥；外部LLM、Embedding、Qdrant仅完成客户端实现和受控故障测试，不是供应商联调通过。
- AI当前为完整JSON响应，不提供SSE token流。单次商品候选最多100个商品/300个SKU，适合首版小校园目录，不是大规模语义商品搜索索引。
- 本地检索评测只有8条人工演示样本，不足以支持毕业论文泛化效果或生产性能结论。
- 单实例服务端会话；未交付跨实例共享会话、SLA、真实压力测试、生产安全评审和自动备份恢复演练。
- 扫描PDF OCR、部分退款、已提货退货、物流配送、真实支付/分账不在既定首版范围。
- 会话删除、细粒度审计留存和高级可观测性未实现；不能把这些非核心后续能力标为完成。

## 迭代中实际发现并修复的问题

- Vue异步列表切换导致旧数据短暂可操作、无稳定key导致操作落到另一行：增加实体key、加载期间禁用主区域、请求序号与主体校验，退出时清理私有数据。
- 网关仅设置响应头超时不够：增加完整异步响应等待超时、取消和1MB正文硬上限，并以真实JDK HTTP检查。
- AI只按单价判断预算会错误推荐多件商品：数量乘单价做总预算和库存限制，新增测试。
- Python分块上传可绕过Content-Length：按实际接收字节数设置4MB硬上限。
- 旧测试/Mapper与新字段不一致：更新方法、表字段、类型映射和专用测试库隔离。
