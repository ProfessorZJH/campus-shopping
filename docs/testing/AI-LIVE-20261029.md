## 实际环境与结果

Python 3.11 的独立工作区虚拟环境安装项目锁定依赖：FastAPI 0.128.2、Uvicorn 0.48.0、httpx 0.28.1、Pydantic 2.13.5、PyMilvus 2.6.17。服务真实绑定本机随机端口并经 TCP 调用；知识向量和文档只存本轮独立 SQLite，没有配置 Qdrant。

| 检查 | 实际结果 |
| --- | --- |
| NVIDIA `nvidia/nemotron-3.5-embed-1b` | `passage`、`query` 均真实返回 2048 维向量，范数约 1 |
| 讯飞 `spark-x2.6` | 真实 `/v2/chat/completions` 返回有效 JSON；导购响应 `mode=LLM` |
| 服务身份 | 5 个内部接口分别拒绝缺少和错误共享密钥，共 10 次 HTTP 401 |
| 真实知识索引、引用、删除 | NVIDIA 生成两个测试文档向量；查询仅引用白名单文档；删除后无引用 |
| 预算、数量、库存 | 20 元预算买两瓶，返回 6 元/瓶的茶共 12 元；礼盒超预算、库存 0、仅剩 1 瓶均排除 |
| 不可售语义候选 | 即使传入语义 SKU 白名单，不足两瓶或超预算也不产生推荐 |
| 多轮召回 | “换一个便宜点的”继承无糖乌龙茶需求 |
| 知识越权诱导 | 原问题复测真实模型拒绝提供内部暗号，引用均来自公开文档 |
| 模型故障降级 | 将模型 URL 指向持有但未监听的本机端口，真实连接拒绝后返回 `LOCAL_FALLBACK` 和显式提示；非供应商实际故障 |
| Milvus 登录 | 用户指定的服务器真实鉴权通过，版本 `pkg/v2.5.4` |

模型 ID、`input_type` 与 MaaS 请求格式核对了 [NVIDIA 官方接口页](https://build.nvidia.com/nvidia/nemotron-3_5-embed-1b)及[讯飞官方 Chat 文档](https://maas.xfyun.cn/doc/guide/3%E3%80%81API%20%E6%8E%A5%E5%8F%A3/3.1%20%E6%98%9F%E7%81%AB%E6%A8%A1%E5%9E%8B%20API/3.1.1%20Chat)；上面的成功结论来自实际请求。

## 首轮失败与连接例外

首轮知识白名单检查断言失败，旧脚本没有保留该次响应，**具体原因无法确定**。脚本已增加失败响应诊断；同一中文问题单独复测返回 `mode=LLM`、明确拒答且仅有授权引用，满足原严格断言。原始失败没有改成 PASS；汇总采用复测结果，不能据此声称模型响应完全稳定。

Milvus 19530 端口未启用 TLS；443 证书主机名不匹配（校验码 62）。首次正常配置检查拒绝了公网 HTTP。向用户说明后，用户指定继续使用现有连接，本次通过验收脚本的显式 `--allow-plaintext-milvus-for-acceptance` 参数执行，报告保留 `encrypted=false`。**TLS 未修复，正常应用的 `Settings.validate` 仍拒绝该公网 HTTP 地址**；这次成功不能作为直接启动正式同步服务的证据。

NVIDIA、讯飞密钥及 Milvus token 保存于 Git 忽略的本地 `.env`，未写入脚本、文档、前端或证据。没有改密码、改远端权限或修改既有集合。`AI_PRODUCT_VECTOR_SYNC_ENABLED` 保持默认关闭。

```powershell
.\var\venv-ai-live\Scripts\python.exe scripts/smoke-ai-live.py --env-file .env --products --output var/ai-live/rerun.json
```

本次按用户指定的现有 HTTP 测试连接执行商品验收及串联：
