# R1 审查整改增量约束

本增量承接 R1、SDD-07/12，保留原分层、交易事实源和短事务。按安全、AI、知识、前端、容量、交付六批实施，执行范围与证据见 [整改记录](../testing/R1-REMEDIATION-20261031.md)。不代表生产部署授权。

## A：安全入口

- 登录、注册、AI 和自提核销的配额使用去除 Servlet context-path 后的业务路径；提取商户 ID 使用同一路径。根路径与 `/campus` 行为相同。
- AI 的 LLM、Embedding、Qdrant、Milvus 地址统一拒绝内嵌凭据、查询、片段和非 HTTP(S) 协议。公网凭据传输使用 HTTPS；HTTP 仅允许回环及服务端明确列入 `AI_TRUSTED_HTTP_HOSTS` 的可信内网对端（默认 Compose 的 `milvus,qdrant`）。可信名单不能填公网服务。HTTP 客户端禁止自动重定向和环境代理。
- `prod` 在 Bean 实例创建前拒绝非 Secure Cookie、未启用或未认证的 Redis、开发命名空间和未配置 `sslMode=VERIFY_IDENTITY` 的 MySQL。禁止重复/旧 TLS 属性及自动公钥检索。CA 通过 JVM/JDBC truststore 提供，证书不可验证时连接失败，不降级。
- 根 Compose 采用生产安全默认值；`compose.local.yml` 仅限回环隔离开发/CI，显式采用 dev profile。旧危险模板和替换运行容器的教学脚本移除，不迁移已有库或替换现有服务。
- 真实供应商验收仅允许手动选择受保护 `main` 的当前 HEAD，使用只允许 main 分支的 `external-ai` Environment。密钥仅在真实调用步骤暴露，使用 `LIVE_*` Environment secrets，缺失则失败关闭。依用户单人维护决定，不要求独立审批。第三方 Actions 固定审核版本的 commit SHA。
- 仓库旧 secrets 无法由 API 读出或迁移；需维护者将其重新存入 Environment 后移除仓库副本。在完成迁移前，不能宣称所有历史工作流的仓库密钥已隔离。新工作流不再引用旧名。

## B：AI 最终约束与评测输入

- Java `ConstraintSet` 从原文独立解析预算、数量、规格及追问继承，不信任模型改写。明确单项数量要求相同数量且最多一项；累加总价不超预算，计算避免溢出；歧义/超限数量和预算不生成提案。Python/Java 共享行为 fixture，不共享模型推断。
- 商品名不能误当未知规格；数量后明确的属性仍受约束。无法解析的强预算/数量不能静默取消。现有确定性语法边界不等同完整自然语言理解。
- Python 所有正文由报价/授权证据模板生成；Java 使用最终报价或验证过的引用片段生成正文，模型不能声称付款、退款或加购已完成。模型选择成功（含合法空选择）可记 LLM；有本地候选且模型未选出任何有效项时记 LOCAL_FALLBACK。
- Java 评测 EXECUTED 必须有两个产品阶段（合法空列表允许）和真实成功 Java/MySQL 来源；语义实验还须匹配 profile 的 Embedding/向量来源。预期实验、唯一性和完整覆盖沿用 PR #15 的强校验。导入资源清理结果在退出码计算前纳入，清理失败或缺证据返回非零。
- `--release-strict` 要求正式人工冻结的数据、完整执行、所需真实来源、硬约束零违规及清理成功。研究运行保留 DRAFT/PARTIAL，不把待审核数据改成已验收。复核 HTML 的所有动态锚点使用类型前缀与 SHA-256，不插入原始 ID。

## C：知识索引与资源一致性

- 领取任务仅允许未占用或600秒租约已过期；独立 token、index_version 和 index_expires_at 保存在 MySQL。完成必须同时匹配 token、文档版本、PENDING 和有效租约，零行更新作为冲突处理。旧任务成功/失败均不能覆盖新任务。
- 领取与配额在短事务中完成，外部提取、Embedding、向量写入不持有数据库事务。发布/撤回先锁 root，再用清理 MyBatis 缓存的当前锁读加载文档；仍要求 READY + root最新版本。
- 商户级配额覆盖其全部知识库，平台知识库使用独立 `__platform__` 配额。实施默认上限1000个持久化文档版本、100MiB提取正文UTF-8、每60秒60次索引领取、同时4个未过期任务。不是原始文件字节配额。已有超限资料保留且阻止继续增长，不自动清理数据。
- 创建文档先原子预占，再创建root/version/document，同一事务失败全部回滚。索引配额行先取排他锁，再检查当前有效任务和领取速率；竞争失败不消耗领取次数，任务完成或租约过期释放并发占用。失败任务已消耗的调用频率不退还，避免重试风暴。
- 新增迁移 `V20261031_02`；旧实例须停止并等待在途请求结束，备份后显式升级。新旧 claim 版本不可混跑。初始化/迁移重放/启动只读校验沿用现有机制，不修改既有迁移，不由应用自动DDL。

## D：前端上下文与分页

- 身份切换和当前身份401统一清理私有数据并重建页面。旧身份的401/CSRF响应不能清理新身份，也不能以新身份重试旧写操作。请求体在调用时快照；GET可取消，写操作失去上下文只丢弃界面回写，不声称服务端已取消。
- 购物车和入驻申请按请求体保持幂等键，相同失败请求重试复用；购物车变更清空键及指纹，内容变化生成新键。加购使用点击时SKU及数量快照。
- 订单、知识库、图片上传回写受身份、路由、商户、页面请求版本/表单上下文约束。切换知识库清空版本root、标题及文件，上传前复核root所属库。公开商户/分类与商品搜索分开控制版本。
- 商户商品分页 `status=LOW_STOCK` 是查询筛选而非聚合状态：已发布商品的全部ACTIVE SKU可售量合计小于20。SELECT与COUNT共用谓词，在分页之前执行；原状态筛选保持兼容。不新增写入状态/权限或迁移。
- 路径ID统一编码，错误转义显示无效地址而不抛URIError。分页展示服务端total；对话框支持焦点约束、Esc关闭与返回触发控件，表格提供真实按钮，输入label关联控件。

## E：容量、恢复与数据外发

- 订单稳定ID游标每轮最多2000笔，失败继续推进，扫尾重新检查，逐订单独立事务幂等。商品全目录keyset扫描每轮4000件，批次远程成功后持久化MySQL checkpoint，跨实例/重启续跑；末尾复位后下一周期重新覆盖更新，不截断公开召回。
- 新迁移V20261031_03保存同步checkpoint；支持显式重放，不由启动升级。锁竞争与Redis故障分别记计数和安全日志。最久逾期及同步成功/失败时间作为告警输入。
- Python授权readiness报告SQLite就绪、实际依赖调用状态及执行容量；外部失败保留本地服务，存储故障503。LLM/Embedding/Qdrant响应先流式限制实际字节再解析，拒绝压缩。
- 内部知识默认禁止外发，商户内部须同时批准商户及知识库，平台内部须批准知识库；未知可见性拒绝。查询逐次传当前批准文档名单，历史远程索引不绕过撤回；正文/历史最小化与基础PII脱敏，审计无原文。详见[操作手册](../operations/R1-capacity-egress.md)。
- 保留单Python及本地持久卷限制，不在本批引入共享SQLite或对象存储。未复现的交易死锁只做真实MySQL并发验证，不扩大重构锁序。
