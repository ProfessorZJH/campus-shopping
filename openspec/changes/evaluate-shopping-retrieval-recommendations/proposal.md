# Proposal

## Why

[PRD FR-023](../../../docs/requirements/PRD.md)要求固定评测集、可重复的召回/约束指标与结果留存；现有入口只覆盖 8 条单答案知识演示样本，尚不能判断校园商品检索、推荐与授权引用的效果。需要把既有设计落实为可复现、可区分环境且能追溯失败的评测能力，而非依据历史联调或局部命中率宣称整体质量提升。

## What Changes

- 版本化合成业务语料、120 条首版分层案例及人工标注规范，分离开发集与冻结验收集；未经人工复核的标签明确标为草稿。
- 复用 `ai-service/evaluate.py`、现有 Python 检索/推荐函数、Java 查询与提案测试、隔离环境启动器，补齐数据验证、分阶段执行、指标、消融与 JSON/Markdown 报告；不另建平台或新增非必要依赖。
- 将知识 chunk/document、商品 product、SKU 候选池与最终推荐分开统计；补充 Recall、Hit、MRR、nDCG、硬约束、覆盖率、引用与安全场景，明确分母和未标注项。
- 独立标识本地算法、受控替身、真实 Embedding、真实 LLM、真实 Milvus 及 Java/MySQL 是否参与；失败/降级/未运行保留独立结果，不混入正常路径的成功数。
- 设计与当前代码匹配的对照实验。历史 E0–E4 保留来源映射，尚无实现的独立 reranker 列为不支持，不为凑实验加入新算法。
- 不改变 Java/MySQL 的价格、库存、经营资格、权限和提案确认边界；评测仅使用隔离数据与专用索引。真实外部调用独立启用并记录实际使用范围。
- 补充授权（Issue #14）：评测暴露规格/否定违规后，修复生产导购的确定性规格过滤并恢复完整CI；规则归[SDD-07第7节](../../../docs/specs/SDD-AI-RECALL-07.md)，不是评测器读取Gold代替生产筛选。保留原始失败与同一数据复验，人工Gold/真实模型/语义评审可在基础设施交付后继续。

## Capabilities

### New Capabilities

- `shopping-ai-evaluation`：智能导购检索、推荐和安全评测的数据契约、执行分层、指标口径、对照实验与证据报告。此为补齐 FR-023 的评测能力，不是重定义现有导购业务。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无能力基线；既有检索、交易、权限规范继续由已接受 SDD 管理，本次不将其伪装为新实现。

## Impact

- 预期实现范围：`ai-service/evaluate.py`、少量共享检索/排序可观察性接缝、现有 pytest/JUnit、隔离验收脚本、版本化评测数据和文档。Java 采集通过测试作用域装饰现有 Port/查询能力，Python 评测复用生产排序函数，不向消费者接口暴露 trace。
- 规格对应：FR-019～023、`evaluation-plan.md`；SDD-07 的全目录召回、SDD-08 的商品 Milvus/融合、SDD-11 的推荐策略与严格契约、SDD-12 的会话/准入边界。详细事实审计、验证边界与逐项映射见 [Design](design.md)。
- 无新生产 API、数据库迁移、前端页面或独立评测服务；不更改模型、分层、交易规则，也不默认启用索引同步。已有 8 条报告保留历史原貌，兼容当前无参数 CI 调用。
- 可观察验收：数据可校验；本地重跑的非计时结果相同；手算多相关项样例与程序指标一致；外部替身不能被计入真实运行；越权/过期/变价/幂等结果可追溯；报告可仅据保存的逐例输出重算。首轮报告建立基线，不预设质量分数或改进幅度。
- 本轮仅创建方案，不生成业务评测结果、不执行真实模型/向量库请求，不修改实现。实现后的本地测试通过也不自动意味着人工标注、真实 AI 或端到端业务验收完成。
