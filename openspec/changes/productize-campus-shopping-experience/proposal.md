# Proposal

> 规划日期：2026-11-05。用户已确认整体方向并授权落盘；本次仅创建规划，业务实现、业务验收、提交合并和部署不因此完成或获授权。实施任务见 [Tasks](tasks.md)，具体设计、审查覆盖与依赖见 [Design](design.md)。

## Why

商品多图与可选七牛存储已经进入主干，现有 12 个业务页面具备交易骨架，但信息完整性、操作连续性和失败恢复仍有缺口。此次将用户提供的全链路静态审查与视觉参考转成覆盖消费者、AI 导购、商户、平台和知识库的分阶段产品化方案，使每项改造都有数据来源、业务边界和可观察的验收条件。

## What Changes

- 保留 Vue 3 + Vite，以紫色主题、清晰导航、卡片、时间线和统一反馈建立三端视觉规范；消费者兼顾手机与桌面，后台以桌面效率为主。先试点标准 `.vue` 组件，再随页面改造迁移；TypeScript 从新增组件和 API 类型试点，包含独立类型检查。
- 优先修复退款申请失败清空表单、引用字段丢失等已定位问题；检查登录、入驻、商品编辑、补货及审核的同类失败行为。新增新对话入口和可靠的推荐详情关联。
- 完善商品发现、价格筛选、商品与店铺详情和结算确认，复用既有多图、SKU、购物车与下单能力。营业信息、标签等新增展示必须有可信来源。
- 增加订单自提地点快照、真实履约事件和售后处理历史；消费者、商户、平台的记录与页面按完整业务链路交付，历史缺失信息不推造。
- 完善 AI 会话切换、最近活跃信息、提案过期及引用展示；单独交付真实 SSE 流式协议与断线、超时、取消语义。SSE 是新增能力，现行完整 JSON 契约在对应增量交付前继续有效。
- 完善商户待办、订单操作、库存可视化、商品与成员管理；完善平台申请审核、监管和争议处理。新增按明确口径聚合的趋势、状态分布和商品表现，不将模拟业务包装为真实财务收益。
- 完善知识版本、索引诊断和引用预览，新增受权限控制的检索调试入口，复用现有检索与评测能力。
- 在每阶段更新受影响的规格、生成契约、测试与使用说明；全链路结果与未验证项保存在 `docs/testing/`。本次不执行这些业务验收。

### Delivery milestones

阶段用于追踪交付，不等于一个阶段只能有一个 PR。编号与此前商品图片第一、第二阶段无关。

| 阶段 | 范围 | 阶段完成条件 |
| --- | --- | --- |
| M0 | 基线、审查追踪、三端设计与接口归属；核对 AI PR #49 交集 | 实施前基线和每批影响明确，具体阻塞与可独立开展的任务分开 |
| M1 | 失败恢复、公共反馈、`.vue` 构建试点、新对话与实时引用 | 首批交互回归通过；开发、离线和 Java 打包保持兼容 |
| M2 | 商品、店铺、结算、订单快照、履约与售后历史 | 消费者与商户能够完成购买、自提及未提货退款分支 |
| M3 | 推荐详情、历史提案与会话体验，随后独立交付 SSE | 跨分页推荐、过期/变价恢复、会话隔离和流式生命周期分别验收 |
| M4 | 商户与平台工作台、审核追踪和必要统计 | 待办可处理、记录可追溯、各角色数据一致且权限有效 |
| M5 | 知识索引诊断、引用预览和 RAG 调试 | 发布、撤回、检索、引用和租户隔离可验证 |
| M6 | 桌面/手机、跨角色、失败与历史兼容的整体验收 | 指定最终版本的业务证据、所需 CI 与未验证范围齐全 |

M1 的独立前端工作不等待 PR #49；M3 的重叠 AI 后端工作须先核对该 PR。M2 的订单/售后记录同时覆盖商户和平台动作，M4 继续改善操作效率。正式域名 HTTPS 复验在备案条件具备后单独推进，不阻塞其余规划。

## Capabilities

### New Capabilities

- [storefront-presentation](specs/storefront-presentation/spec.md)：价格范围筛选、可信门店展示与跨入口商品详情体验的增量。
- [checkout-confirmation](specs/checkout-confirmation/spec.md)：提交前确认以及价格、库存或可售状态变化后的恢复体验。
- [order-progress](specs/order-progress/spec.md)：稳定的自提地点展示及基于真实记录的履约进度。
- [aftersale-history](specs/aftersale-history/spec.md)：消费者、商户与平台共享的售后阶段、决定及历史可见性。
- [guide-conversation-experience](specs/guide-conversation-experience/spec.md)：新会话、最近活跃历史、完整引用及独立于商品列表缓存的推荐导航。
- [ai-response-streaming](specs/ai-response-streaming/spec.md)：实际增量响应与明确的流式结束、失败、断线和取消反馈。
- [operations-dashboard](specs/operations-dashboard/spec.md)：商户待办、库存定位与按明确口径生成的经营/平台查询展示。
- [operations-review-history](specs/operations-review-history/spec.md)：申请审核、监管与争议处理的授权历史查询和可追溯展示。
- [knowledge-retrieval-debugging](specs/knowledge-retrieval-debugging/spec.md)：授权范围内的检索调试、索引诊断与引用核对。

### Modified Capabilities

无已有 OpenSpec 能力基线需要在本次规划中直接修改：`openspec list --specs --json` 当前为空。上述 delta 仅定义拟新增的体验、读模型与流式能力；退款失败恢复等既有行为缺陷继续引用 R1/既有 UI 规格修复，不将整个商城、权限或交易规则重新声明成新能力。

尚未迁移的规则继续由已接受 SDD/ADR 管理；首次同步能力基线时按 [OpenSpec 资料归属](../../../docs/development/OPENSPEC.md)核对边界并更新旧文档引用。此处没有把待实施 delta 发布为当前业务契约。

- **预期实现范围**：`frontend/src`、前端构建/测试、相关 Java API/Case/领域/查询与持久化、AI HTTP Port/Python、必要的新迁移及契约。具体依赖和落点由 [Design](design.md)维护。本次文件变化限定为本变更目录及文档入口。
- **不变量**：沿用 [R1](../../../docs/specs/RELEASE-01.md)、[行为契约](../../../docs/api/behavior-v1.1.md)、[SDD-12](../../../docs/specs/SDD-REDIS-12.md)与已接受 ADR。Java/MySQL 裁决价格、库存、权限与成交；保留同库事务、稳定锁序、幂等、CSRF、600 秒会话租约与实际执行期间的 Python 许可。
