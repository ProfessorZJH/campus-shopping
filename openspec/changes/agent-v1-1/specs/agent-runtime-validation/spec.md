# Spec Delta

## Purpose

为 Agent v1.1 建立真实运行时的可重复验收边界，证明模型确实产生原生工具调用并能在隔离的商品向量集合中完成检索，再用 Java/MySQL 事实复验结果，同时留下故障、成本、清理和未运行范围的证据。

## ADDED Requirements

### Requirement: 真实模型必须产生原生工具调用

M1 验收 SHALL 使用真实配置的模型服务验证结构化 Function Calling；仅输出看似工具调用的普通文本不得计为成功。

#### Scenario: 模型发出合法原生调用

- **WHEN** 真实模型针对工具声明返回函数名和符合 JSON Schema 的参数
- **THEN** 运行时记录原生工具调用、执行工具并把结构化回执交回模型生成后续回答

#### Scenario: 模型只输出伪造调用文本

- **WHEN** 模型输出“调用 search_products”之类的文本但没有可解析的原生工具调用结构
- **THEN** 验收标记该样本失败或降级，不执行由文本推断出的工具，不记为 Tool Calling 通过

### Requirement: 结构化参数和工具回执必须可验证

运行时 SHALL 对工具名称、必填参数、类型、范围和回执结构执行验证；未知工具、缺失参数、伪造参数和非法回执必须安全终止当前工具步骤。

#### Scenario: 合法参数完成一轮

- **WHEN** 模型提供已登记工具和完整参数，工具返回符合约定的只读回执
- **THEN** 系统把回执交回模型，模型可以继续回答，且记录工具调用次数和结果状态

#### Scenario: 非法参数被拒绝

- **WHEN** 模型省略必填参数、注入未声明字段、使用错误类型或请求不可读资源
- **THEN** 系统拒绝执行工具，返回结构化失败，并记录失败原因而不执行兜底写入

### Requirement: 真实商品检索必须经过隔离 Milvus 和 Java 事实复验

M1 SHALL 使用独立测试集合完成商品向量的写入、检索、更新、删除和清理；召回 ID 返回后必须通过 Java/MySQL 重新核对当前商品、SKU、价格、库存和可售状态。

#### Scenario: 隔离集合完成全生命周期

- **WHEN** 测试为本次运行创建随机命名的 Milvus 集合并执行索引、检索、更新、删除和清理
- **THEN** 记录集合名称、运行标识、每步结果和清理证据，且生产商品集合保持不变

#### Scenario: 向量召回与事实不一致

- **WHEN** Milvus 返回不存在、已下架、无库存或价格版本过期的商品 ID
- **THEN** Java/MySQL 复验移除或标记该候选，运行时不得把向量结果当作可交易事实

### Requirement: 流式和上游故障必须有明确结果

真实运行时 SHALL 对流式工具参数、超时、429、5xx、连接中断和异常终止产生可判定结果，并在可支持时安全降级到既有 RAG/导购。

#### Scenario: 流式工具参数完整到达

- **WHEN** 工具调用参数分片在流式响应中按协议完成，且最终 JSON 可验证
- **THEN** 系统只执行一次工具，并把工具回执与后续模型输出关联到同一轮

#### Scenario: 上游返回 429 或 5xx

- **WHEN** 模型或 Embedding 服务返回 429、5xx、超时或连接异常
- **THEN** 系统停止当前失败步骤，记录对应故障类型，并按策略返回安全失败或 `DEGRADED`，不伪造成功回执

### Requirement: 运行指标和证据状态必须完整

每个真实样本 SHALL 记录模型/Embedding/向量服务配置标识、总时长、工具次数、Token 或可得成本、结果状态和未运行原因；证据状态只能使用 `REAL`、`STUB`、`DEGRADED` 或 `NOT_RUN`。

#### Scenario: 真实样本成功

- **WHEN** 真实模型、真实 HTTP 服务、隔离 Milvus 和 Java 事实复验均完成
- **THEN** 报告记录 `REAL` 及可核对的时延、调用次数、Token/成本和运行标识

#### Scenario: 真实依赖未配置

- **WHEN** 真实供应商凭据、Milvus 或所需网络服务未配置或未执行
- **THEN** 报告记录 `NOT_RUN` 或实际的 `STUB`/`DEGRADED` 原因，不把 CI 通过或替身结果表述为真实验收

### Requirement: 追踪和日志必须脱敏

运行时 SHALL 在 Trace、日志和验收报告中隐藏凭据、授权头、完整提示词、私有文档正文和下游异常正文，只保留可定位的安全摘要。

#### Scenario: 上游返回敏感错误

- **WHEN** 模型、Milvus 或 HTTP 服务错误正文包含密钥、授权信息或内部内容
- **THEN** 对外结果、日志和报告只保留脱敏错误类型与运行标识，不写入原文

### Requirement: M1 不改变现有交易入口

M1 验收 SHALL 在实验环境或受控测试入口内完成，不新增公开 Agent 用户入口，不直接写购物车、订单、库存或支付，不创建生产 `ai_run` 运行记录。

#### Scenario: 运行时验证完成

- **WHEN** M1 的真实模型、工具和 Milvus 测试全部结束
- **THEN** 仅产生测试报告、诊断数据和可清理的隔离索引证据，现有导购和交易接口行为保持不变

#### Scenario: 实验请求试图执行写操作

- **WHEN** 测试样本要求购物车、订单、库存或支付变更
- **THEN** 系统拒绝该样本或标记为未覆盖，不修改业务库，不把模型回答当成成功回执
