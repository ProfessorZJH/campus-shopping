# 校园导购评测集 v1（草稿）

本目录是公开合成数据，不是线上商品/用户数据。固定120场景、12主类，48开发/72验收，12条smoke均属于开发集；一次对话/状态变更是一例，不能按请求次数扩充样本量。

生成：在 `ai-service` 运行 `python -m evaluation.generate`。验证器核对清单摘要、ID/外键、金额/库存/状态、标签版本、身份范围、划分/问题家族与近重复。已复核版本不能由生成器覆盖。240商品360SKU、24知识版本和6商户仅为起始分布，不构成真实需求代表性。

## 人工标注

1. 先看完整商品/知识快照和问题，不看被测模型输出；0=无关/违背意图，1=背景/部分相关，2=直接满足检索意图。列出完整相关集，不只对召回结果打分。库存/预算可行性与主题相关性分开。
2.核对每条case的预算合计、数量、规格/否定要求、角色、授权文档、预期推荐/无匹配/澄清与状态变化。知识引用必须指出版本/正文位置；没有证据的内容不是正确答案。案例允许多种正确回答，不要求逐字匹配。
3. `qrels.jsonl` 为分级相关性；`annotations.jsonl` 保存实际reviewer、reviewedAt、依据、分歧与case/qrels摘要。AI生成记录固定为AI_ASSISTED/DRAFT；人工实际复核后才改HUMAN_REVIEWED，不能批量把未看过的标签勾成通过。
4. 建议安全样本及20%质量样本复审；只有一人时记singleReviewer，不称独立双人。存在分歧先裁决；跨split近重复由人工检查并在manifest的reviewedNearDuplicates逐对记录，不允许模型自己认定无污染。
5. 所有标签人工完成后才可冻结ACCEPTED，并重算manifest文件SHA-256。修改文本/标签产生新版本，不能保持旧摘要。正式命令拒绝DRAFT、未决分歧、缺少人工记录；探索命令保持DRAFT报告。

`caseHash`/`qrelsHash` 使用 `evaluation.dataset.digest` 的规范JSON摘要。语义支撑/语义泄漏评审是运行后的独立人工工作；自动canary检查和引用定位不能替代它。旧8条演示样本不是本目录gold。
